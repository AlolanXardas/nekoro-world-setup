World rules for modpacks and servers, all set in config files.
Everything starts off, apart from a fix for a world generation crash, so the mod does nothing until you turn something on.
Made for my Nekoro Pokemon modpack, but it works in any world.

Required on the client and the server.

All my projects are being prepared for a big update of my modpack. I'm changing them step by step so they fit together, and they should be ready by the end of this year.

Features

Start commands and game rules

  • Game rules set when a world is created, or again on every server start. Modded game rules too.
  • Commands run when the world is created, on every server start, on a player's first join or on every join.

Enchantment levels

  • Higher maximum levels for the enchanting table, anvil, books and /enchant, with a different maximum per enchantment if you want.
  • An adjustable or removed "Too Expensive!" limit.
  • Every Mending level above I repairs more per XP point.
  • Higher Silk Touch levels also work with Nekoro Random Drop: rules with "silk_touch": "bonus" get a higher chance with each level.

Enchantment rules

  • Enchantments that normally exclude each other can be combined: Sharpness with Smite, the Protections, Fortune with Silk Touch...
  • Enchantments can go on extra items, like Looting on axes.
  • Feather Falling protects farmland, Infinity works without arrows, Looting and Fortune give more XP, all Multishot arrows hit, shears and shields work in the enchanting table.

Bone meal

  • Also works on sugar cane, cactus, vines, nether wart, full melon and pumpkin stems, lily pads, small flowers, dead bushes, chorus, coral in warm oceans, spore blossoms, podzol, mycelium and dirt next to grass.
  • Each one has its own option.

Mob filters

  • Block mobs, or allow only the ones you list, by id, whole mod or tag.
  • Choose which kinds of spawning are checked: natural, spawners, structures, breeding, spawn eggs...
  • Optionally remove blocked mobs that already exist, and block mobs that appear without a normal spawn, like bees leaving hives.

Ore removal

  • Remove ores from vanilla and mods, the big ore veins too, with a list of ores to keep.
  • In my modpack ores come from mining stone with Nekoro Random Drop instead.

Cave removal

  • Remove cave tunnels and canyons, spaghetti and noodle caves, and the big open caves, Terralith's too.
  • Remove lava lakes, lava springs, the deep lava layer and geodes.

Recipes

  • Remove recipes by result, recipe id, mod or tag.
  • Add recipes: slabs and stairs back to blocks, logs to sticks, logs to chests.

Other features

  • Global datapacks: Datapacks from config/Nekoro/WorldSetup/datapacks load in every world, new and existing.
  • Water at the shore: Digging sand, dirt or gravel next to water fills its place with water right away, so beaches don't end up flooded. Built blocks are left out.
  • Lava and water: They no longer make cobblestone or stone. Basalt and obsidian can be turned off too.
  • World edge: Walking out of a square area takes players to the opposite side, like on a round planet.
  • Void: Players who fall into the void appear at the top of the dimension and fall back down.
  • Real time: The time of day can follow the clock of the computer the server runs on.
  • Flat bedrock: A flat bedrock floor and Nether roof.
  • Feature order fix: When biome mods place the same features in opposite orders, vanilla stops world generation with "Feature order cycle found". This fix is on by default, lets the world generate and writes the features to the log.

More information

Config

  • All files are in config/Nekoro/WorldSetup/ and every option is explained in the file.
  • start.json: game rules, commands, datapacks.
  • world.json: enchantments, bone meal, water and lava, world edge, void, real time.
  • mobs.json: mob filters.
  • worldgen.json: bedrock, ores, caves, the feature order fix.
  • recipes.json: recipes.
  • /reload applies changes to world.json, mobs.json and recipes.json. start.json and worldgen.json need a restart, and world generation changes only affect new chunks.
